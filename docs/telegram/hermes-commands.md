# Hermes Agent commands and the AHAWR bot

Source: `hermes_cli/commands.py` of the Hermes Agent in `D:/Hermes/hermes-agent` (102 commands, registry `COMMAND_REGISTRY`; generated by reading the file, nothing imported). Hermes serves the same commands in its CLI and its messaging gateway (Telegram, Discord, ...): `cli_only` ones exist only in the terminal, `gateway_only` only in chats.

Conventions to copy: a command has a canonical name, aliases, an argument hint (`[optional]`, `<required>`) and a category (Session, Configuration, Info, Tools & Skills); `/help` lists the short form grouped by category, `/commands [page]` pages through everything; Hermes registers its commands with Telegram (`setMyCommands`) so they show up in the bot menu. Telegram command names allow only `a-z`, `0-9`, `_` (up to 32 characters), so a name like `reload-mcp` is offered as `/reload_mcp`.

IMPORTANT: one Telegram bot token can have only ONE consumer of `getUpdates`. If Hermes' own Telegram gateway is connected, it needs its own bot (its own token); the AHAWR bot must not share it.

## What the AHAWR bot takes from Hermes

| Hermes command | Category | Scope in Hermes | AHAWR | What it does in AHAWR |
|---|---|---|---|---|
| `/start` | Session | chat only | adopt | First contact: short greeting and a pointer to /help (only for allowed chats; others get nothing). |
| `/help [skills\|<filter>]` | Info | CLI and chat | adopt | Short list grouped by category (Hermes style); `/help <text>` filters. |
| `/commands [page]` | Info | chat only | adopt | Paginated full list: `/commands [page]`. |
| `/status` | Session | CLI and chat | adapt | Mission status: progress, task, attempt, last scores, Worker/Reviewer state, time, llama-server and runner health. `/status [mission]`. |
| `/whoami` | Info | CLI and chat | adopt | Access level of this chat: admin (control and edit) or viewer (read-only). |
| `/stop` | Session | CLI and chat | adapt | Stop the running AHAWR execution (confirmation). Leaves no run in state "running" without an owner. |
| `/pause [reason \| off]` | Session | chat only | adapt | `/pause [reason | off]`: no new task starts after the current one finishes (flag in the config table, checked before each task); `/pause off` resumes. Global emergency brake. |
| `/resume [name]` | Session | CLI and chat | adapt | Continue a mission from its saved state: `/resume [mission]`. |
| `/restart` | Session | chat only | adapt | Stop, wait for the active run to drain, start again from the saved state (confirmation). |
| `/retry` | Session | CLI and chat | adapt | One more attempt of the current task with the last review as feedback (the manual "extra attempt" procedure). |
| `/undo [N]` | Session | CLI and chat | adapt | `/undo [N]`: roll back the last N mission or config edits from the edit history. |
| `/approve [session\|always]` | Session | chat only | adapt | Confirm the pending change (same as the inline button); `/approve` without a pending change says so. |
| `/deny [all] [reason]` | Session | chat only | adapt | Cancel the pending change (same as the inline button). |
| `/config` | Configuration | CLI only | adapt | Show the editable config keys with their current values and allowed ranges (never secrets). |
| `/model [model] [--provider name] [--reasoning level] [--global\|--session] [--refresh]` | Configuration | CLI and chat | adapt | `/model <role> <model> [--provider name]`: change the model or provider of architect, worker, reviewer or service (confirmation, audit). |
| `/agents` | Session | CLI and chat | adapt | Active agent runs from claude-runner (role, task, time, tokens) and the n8n execution. Alias /tasks. |
| `/usage [reset [--force]]` | Info | CLI and chat | adapt | Tokens, tokens per second, cache share and time per task of the current mission, from the runner events. |
| `/insights [days]` | Info | CLI and chat | adapt | `/insights [days]`: scores and retries per task over the last N days, slowest tasks. |
| `/profile` | Info | CLI and chat | adapt | The active hermes_config profile (e.g. claude-code) and the chat that is allowed. |
| `/version` | Info | CLI and chat | adapt | Versions: workflow, bot, Claude Code in the runner, n8n. |
| `/sethome` | Session | chat only | adapt | Add this chat to the allow-list (admin only, with a one-time code shown in the n8n log; no secrets in the chat). |
| `/queue [<prompt>\|list\|edit N <prompt>\|rm N\|move A B\|clear]` | Session | CLI and chat | adapt | Our own meaning: a queue of MISSIONS. `/queue [add <mission>|list|rm N|move A B|clear]`; the next mission starts when the current one is approved. |
| `/steer <prompt>` | Session | CLI and chat | adapt | Operator note for the current task: appended to the feedback of the next attempt (`/steer <text>`). |
| `/debug [nous\|local]` | Info | CLI and chat | adapt | Our `/errors [N]`: the last failed executions with node name and message (secrets masked). |
| `/tools [list\|disable\|enable] [name...]` | Tools & Skills | CLI only | later | After mission ahawr-hermes-dashboard-parity: `/tools <role> list|disable|enable <tool>` edits the role tool restrictions. |
| `/cron [subcommand]` | Tools & Skills | CLI only | later | Scheduled mission start (`/schedule`), not in the first version. |

## What the AHAWR bot adds (no Hermes equivalent)

| Command | What it does |
|---|---|
| `/missions` | List of missions: id, name, enabled, version. |
| `/mission <id> [enable|disable]` | Details of one mission; enable or disable it (confirmation). |
| `/mission <id> edit <field> ...` | Edit name, working folder, objective; `rule add|del|set N <text>` and `criterion add|del|set N <text>` for the rule and criteria lists. Raises the mission version and keeps the old one for /undo. |
| `/progress [mission]` | The plan with the score and attempt count of every task (Hermes /tasks means running agents, so the plan view has another name). |
| `/start <mission>` | Hermes /start is only a greeting; in AHAWR `/start <mission>` with an argument starts a mission (confirmation), without an argument it is the greeting. |
| `/accept [reason]` | Accept the current task by hand and go to the next one; the reason goes to the audit log. |
| `/set <key> <value>` | Edit one config value from the allow-list with type and range checks. |
| `/audit [N]` | The last N entries of the audit log (who, when, command, before, after, result). |
